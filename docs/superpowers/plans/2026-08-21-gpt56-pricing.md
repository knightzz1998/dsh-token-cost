# GPT-5.6 Pricing Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make dsh-token-cost price GPT-5.6 Luna, Terra, and Sol correctly across OpenAI, OpenAI Codex, and OpenRouter routes, including long-context tiers.

**Architecture:** Keep pricing configuration-driven and preserve the existing pure session projection. Extend each model spec with optional token threshold tiers; resolve exact route first, then model aliases, and never silently apply DeepSeek pricing to an unknown route.

**Tech Stack:** Hand-written JavaScript ESM host plugin, Schemastery, Zod, Node test scripts, Cordis session projections, YAML profile configuration.

## Global Constraints

- Prices are USD per 1,000,000 tokens.
- Exact route keys use `<provider>/<model>`; model-only aliases remain supported.
- GPT-5.6 prices come from the local runtime model registry shipped with `@earendil-works/pi-ai`.
- DeepSeek remains the default pricing route; unknown routes must be visibly marked rather than silently charged at DeepSeek rates.
- Changes must update local profile configuration and the public GitHub repository.
